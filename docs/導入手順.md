# QA試験v2 導入手順（DB登録・保存・NGメール）

> 同梱の `QA試験v2.2.xlsm` と `QA試験DB.odb` をそのまま使う場合、1・2・4 は済んでいます。0 を確認し、ダウンロードしたブックの［許可する］（README の使い方 2）をしてから、3（フォーム作成）、5、6 に進んでください。
> 1〜4 は、自分のブックに組み込む場合や、DB を作り直す場合の手順です。

## 0. 用意するもの
| もの | 確認 |
|---|---|
| Excel（デスクトップ版） | マクロ有効ブック QA試験v2.2.xlsm が開ける |
| LibreOffice 26.2 | 一度ふつうに起動して、初回の画面を閉じておく |
| Gmail | 既定のブラウザで Gmail にログインしておく（NG のとき、ここに下書きの作成画面が開く） |
| `src_sjis\` の .bas 11個と ThisWorkbook.txt | Shift_JIS のファイル（`src\` は GitHub で読む用の UTF-8 なので、取り込みには使わない） |
| `sql\検査データ_作成.sql` | テーブルを作り直す SQL |

- ブックと DB は OneDrive の同期フォルダ以外に置く（パスが https:// になると DB 登録が止まる）。

## 1. DB（QA試験DB.odb）のテーブルを作り直す
1. `QA試験DB.odb` を QA試験v2.2.xlsm と同じフォルダに置く（別の場所なら、5 で設定シートにパスを書く）。
2. ダブルクリックして Base で開く。
   - 「Java が必要」「Firebird に移行」などの画面が出た場合は、移行せずに閉じて知らせる（埋め込み HSQLDB は Java が必要な場合がある）。
3. ［ツール］→［SQL...］を開き、`検査データ_作成.sql` の中身をすべて貼り付けて［実行］。
4. ［表示］→［テーブルの更新］。テーブル「検査データ」を開き、列が ID・品名・ロット番号・状態・日付・検査日時・NG回数・検査名・判定結果・検査項目1〜10・検査員 になっていることを確認する。
   - 前の版の SQL で作ったテーブルがある場合も、この SQL で作り直す（中のデータは消える）。
5. Base を保存して閉じる（閉じないと Excel から登録できない）。

## 2. VBA を取り込む
1. QA試験v2.2.xlsm を開き、Alt＋F11 で VBE を開く。
2. 古いモジュール（modAccess など）や古いフォーム（frmApprover）が残っていれば削除する（右クリック →［解放］→ エクスポートは［いいえ］）。
3. ［ファイル］→［ファイルのインポート］で、`src_sjis\` の次の .bas を1つずつ取り込む。
   `modCommon` `modCover` `modDetail` `modStamp` `modMaster` `modSave` `modSetup` `modMail` `modBaseDB` `modForms` `modTest`
4. プロジェクトの「ThisWorkbook」をダブルクリックし、中身を消してから `src_sjis\ThisWorkbook.txt` の内容を貼り付ける。
5. ［デバッグ］→［VBAProject のコンパイル］。エラーが出たら、出た行とメッセージを知らせる。
6. ブックを上書き保存する。

## 3. フォームを作る（押す人の選択・保存形式の選択）
1. Excel の［ファイル］→［オプション］→［トラスト センター］→［トラスト センターの設定］→［マクロの設定］で、「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」にチェックを入れる。
2. ［開発］→［マクロ］から `フォーム作成` を実行する。「作成したフォーム：frmApprover frmSaveType」と出ればよい（既にあるフォームは作らない）。
   - 前の版で作った `frmPassword` が残っていれば削除する（右クリック →［解放］）。残っているとコンパイルエラーになる。
3. 1 のチェックは外してよい。
4. ブックを上書き保存する。

## 4. 表紙のボタンと設定シートを作り直す
1. マクロ `表紙ボタンと設定の更新` を実行し、「はい」を押す。
2. 表紙の右のボタンが「承認者 押印／担当者 押印／保存／DB登録／表紙削除／一括削除」の6つになったことを確認する。

## 5. 設定シートを書く
| セル | 内容 |
|---|---|
| C3 | DB ファイルのパス。ブックと同じフォルダの QA試験DB.odb なら空欄 |
| C6 | 下書きを開く Gmail アカウント（任意）。複数の Google アカウントでログインしているときに指定する。空欄ならログイン中のアカウント |
| C7 | NG メールの宛先（複数は `,` 区切り）。空欄だと下書きを作らない |
| C8 | CC（任意） |
| C9 | 件名（空欄なら「【NG】QA試験 品名 ロット番号」） |

## 6. 動作確認
| # | 操作 | 成功の確認 |
|---|---|---|
| 1 | 表紙に品名・ロット番号・日付を入れる | 明細シートができる |
| 2 | 全明細で、基準に合う検査項目と OK欄（すべて OK）を入れ、検査者押印 | 表紙の総合判定が OK |
| 2-2 | 基準に合わない値（例：300℃以上なのに 290）を入れ、OK欄は OK のまま検査者押印 | 「OK欄が基準と合いません」と、セル・検査値・基準での判定が出て、押印されない。OK欄を NG にすれば押せる |
| 2-3 | 数値のルールの検査項目に文字を入れる／空欄のまま検査者押印 | 「基準で判定できない検査項目があります」と出て、押印されない |
| 2-4 | 一致のルール（抜き取りなど）で、小文字・全角（例：ｃ）を入れて OK | 大文字・半角と同じとみなして押印される |
| 3 | 表紙「保存」→ Excel と PDF にチェック → OK → 保存先を選ぶ | 選んだフォルダの中に「Excel」「PDF」フォルダができ、それぞれに保存される。名前に【NG】が無い。保存履歴に Excel・PDF の2行 |
| 4 | 表紙「DB登録」 | 「登録しました（○件、判定 OK）」。Base で開くと行が増えている。検査日時が 3 の Excel 保存の時刻と同じ、NG回数が 0 |
| 5 | もう一度「DB登録」→「いいえ」 | 何も変わらない。「はい」なら登録し直され、件数は増えない |
| 6 | Base で QA試験DB.odb を開いたまま「DB登録」 | 「DB ファイルが開かれています」と出て止まる |
| 7 | 新しいロット番号にして、Excel を保存せずに「DB登録」 | 「Excel 保存がありません」と出て止まる |
| 8 | どれか1つの OK欄を NG にして検査者押印 → 「保存」 | 形式を選ぶ画面は出ず、`【NG】品名_ロット_日付` の Excel・PDF が保存される。その後、ブラウザで Gmail の作成画面が開き（宛先・件名・本文入り）、「PDF」フォルダが PDF を選んだ状態で開く。メールは送信されない。保存履歴に Excel・PDF・メール下書きの行。件名・本文の日本語が文字化けしていないかも見る |
| 9 | 8 の後、続けて「DB登録」 | 「登録しました（○件、NG 1回目）」。Base で NG回数 1 の行が増え、4 の行（NG回数 0）は残っている |
| 10 | もう一度「保存」→「DB登録」 | ファイル名の末尾が `_2回目`。下書きの本文の NG 回数が 2回目。DB に NG回数 2 の行が増える |
| 11 | 表紙か明細の入力（検査項目・OK欄・状態など）を1つ変えて、保存せずに「DB登録」 | 「保存の後に入力が変わっています。保存し直してください」と出て止まる（OK/NG が変わらなくても止まる）。「保存」した後なら登録できる |
| 12 | 設定シート C7 を空にして「保存」（NG のとき） | 「宛先が設定されていません」と出て下書きは開かないが、ファイルは保存される |
| 13 | 判定 OK のときに「保存」→ 何もチェックせずに OK | 「Excel か PDF の少なくとも1つを選んでください」と出る |
| 14 | マクロ `テスト実行` | 「テスト結果」シートの NG が 0 件（LibreOffice・DB が無い環境では Base 登録が SKIP） |

`テスト実行` は表紙と明細の入力中のデータを消すので、入力が無い状態で実行する。DB は本番のファイルではなく、一時フォルダのコピーを使う。

## 7. 困ったとき
| 症状 | 対処 |
|---|---|
| Base を閉じても「DB ファイルが開かれています」と出る | LibreOffice をすべて閉じる。それでも出る場合は、DB と同じフォルダの隠しファイル `.~lock.QA試験DB.odb#` を削除する（エクスプローラーの［表示］で隠しファイルを表示する） |
| 「LibreOffice を起動できません」 | LibreOffice がインストールされているか確認し、一度ふつうに起動してから再実行する |
| Gmail の作成画面ではなく受信トレイやログイン画面が開く | 既定のブラウザで Gmail にログインしてから、もう一度「保存」する。別のアカウントで開く場合は設定シート C6 にそのアドレスを書く |
| 「Gmail の作成画面を開けませんでした」 | 既定のブラウザが設定されているか確認する。メッセージの内容を知らせる |
| 前の版の frmPassword が残っていてコンパイルエラー | VBE で frmPassword を削除する |
| 「フォームを表示できません」 | 3 の `フォーム作成` を実行する |
