# QA試験v2 仕様書（DB登録・保存・NGメール）

> 対象：`QA試験v2.2.xlsm`（表紙／明細シート構成の Excel VBA）と `QA試験DB.odb`（LibreOffice Base）
> 版：2026-11-19 作り直し（以前の CLAUDE.md・仕様書・VBA はすべて破棄し、この版を正とする）
> 2026-11-19 改訂：NG は保存後に PDF を添付してメール、NG 2回目以降のファイル名に「_n回目」、DB に NG 回数ごとに残す
> 2026-11-19 改訂：NG メールは送信せず、Gmail の作成画面（下書き）を開くところで終わる仕様に変更
> 2026-11-19 改訂：Excel／PDF を保存先の中の「Excel」「PDF」フォルダに分けて保存。検査値を基準で判定し、OK欄との食い違いで押印を止める

---

## 1. 目的
- 検査結果を LibreOffice Base に蓄積し、後から品名・ロット・期間で検索できるようにする
- NG のときに自動でメールを送り、保存ファイル名で NG と分かるようにする
- 表紙のボタンを整理する（保存は1つのボタンで Excel/PDF を選ぶ）

## 2. 決定事項
| # | 内容 | 決定 |
|---|---|---|
| 1 | DB | 埋め込み HSQLDB（LibreOffice 26.2 で使えればよい）。テーブルは「検査データ」1つ |
| 2 | テーブル | 作り直す（自動採番・検査項目は文字列・検査日時） |
| 3 | DB ファイルの既定名 | `QA試験DB.odb`（設定シートが空欄のとき、ブックと同じフォルダ） |
| 4 | 登録の単位 | 明細シート1枚（検査1つ）＝1行 |
| 5 | 登録のタイミング | 表紙の「DB登録」ボタン |
| 6 | 検査日時 | 保存履歴にある、同じ品名・ロットの最新の Excel 保存の時刻。無ければ登録しない |
| 7 | 検査員 | 明細シートの検査者印の名前（電子印鑑シートの氏名） |
| 8 | 重複・NG の履歴 | NG は回数ごとに別の行で残す（列「NG回数」：NG の保存なら何回目か、OK の保存なら 0）。同じ品名＋ロット番号＋NG回数が登録済みのときだけ上書きを確認し、「はい」でその回数の行を削除して登録し直す |
| 9 | Access 登録 | 削除 |
| 10 | 保存ボタン | 「Excel保存」「PDF保存」「一括保存」を削除し、「保存」ボタン1つにする。フォームのチェックボックスで Excel／PDF を選ぶ（両方可） |
| 11 | NG メール | 表紙の総合判定が NG のとき、「保存」ボタンで Excel・PDF を保存した**後に**、Gmail の作成画面（下書き）を開く。**送信はしない**（決定#16）。開いたら保存履歴に記録 |
| 12 | 【NG】 | 総合判定が NG のとき、保存ファイル名の先頭に【NG】を付ける（Excel・PDF とも） |
| 14 | NG の保存形式 | NG のときは形式を選ばせず、Excel・PDF の両方を必ず保存する |
| 17 | 保存先のフォルダ | 保存のたびに選んだフォルダの中の「Excel」フォルダに Excel、「PDF」フォルダに PDF を保存する（無ければ作る） |
| 18 | 基準での判定 | 検査者押印のとき、検査値をマスタのルール（以上／以下／範囲／一致）と基準値で判定し、人が入れた OK欄と比べる。食い違う行、判定できない値（数値のルールで空欄・数値でない）があれば押印しない（6.7） |
| 16 | 下書きの作り方 | 既定のブラウザで Gmail の新規メール作成画面（`https://mail.google.com/mail/?view=cm`）を、宛先・CC・件名・本文を入れて開く。PDF は自動では添付できないため、PDF を選んだ状態で保存先フォルダを開き、人がドラッグして添付・送信する。パスワードは使わない |
| 15 | NG 2回目以降 | 同じ品名・ロットの NG の保存が2回目以降なら、ファイル名の末尾に「_2回目」「_3回目」…を付ける（Excel・PDF とも）。例：`【NG】AAA-111_S-LP999999_20260901_2回目.xlsx` |
| 13 | フォーム | frmApprover・frmSaveType はマクロ「フォーム作成」で自動作成する（.frx を使わない） |

## 3. 全体構成
```
[QA試験v2.2.xlsm]
 表紙   ：承認者 押印／担当者 押印／保存／DB登録／表紙削除／一括削除
 明細_* ：検査者押印／明細削除
 マスタ・電子印鑑・設定・保存履歴
      │ 保存（NG なら【NG】付きで Excel・PDF を保存 → Gmail の作成画面を開く）
      │ DB登録 ──(VBA → LibreOffice を COM/UNO で操作)──▶ [QA試験DB.odb] 埋め込み HSQLDB「検査データ」
```
- 接続：`CreateObject("com.sun.star.ServiceManager")` → .odb を非表示で開く → `DataSource.getIsolatedConnection`（`getConnection` は共用の接続でトランザクションが使えないため） → `prepareStatement`
- 埋め込み DB は `store()` しないと変更が残らないため、登録後に必ず保存する
- 埋め込み HSQLDB は ODBC/ADO では接続できない

## 6. 機能
### 6.1 保存（`検査表保存`）
1. 総合判定が OK など NG 以外なら、frmSaveType で Excel／PDF を選ぶ（1つも選ばないと OK できない。キャンセルで終了）。NG なら選ばせず両方
2. 既存の確認（判定・印鑑の不足があれば続けるか確認）、品名・ロット・日付のチェック、保存先フォルダの選択
3. 保存先の中の「Excel」「PDF」フォルダを使う（保存する形式の分だけ。無ければ作る。作れなければ止める）。NG なら、ファイル名の先頭に【NG】。NG 回数（保存履歴の、同じ品名・ロットで【NG】付きの Excel 保存の数＋1）が2以上なら末尾に「_n回目」
4. 保存する形式すべての上書き確認を先に行う（途中で「いいえ」なら何も保存せず、メールも送らない）
5. Excel・PDF を保存し、それぞれ保存履歴に1行
6. NG なら NG メールの下書き（Gmail の作成画面）と、PDF を選んだ状態の保存先フォルダを開き、保存履歴に1行（種類＝メール下書き、保存先＝宛先）
7. ブックを上書き保存し、結果を表示（メールの成否も表示）

### 6.2 NG メール（modMail）
- 開き方：`https://mail.google.com/mail/?view=cm&fs=1&to=…&cc=…&su=…&body=…&authuser=…` を `Shell.Application.ShellExecute` で既定のブラウザに渡す。値は `ENCODEURL`（UTF-8）で変換する
- Gmail アカウント・宛先・CC・件名：設定シート C6・C7・C8・C9。宛先が空欄なら開かない。アカウントが空欄ならログイン中のアカウント。件名が空欄なら「【NG】QA試験 品名 ロット番号」
- 添付：自動ではできない。PDF を選んだ状態で保存先フォルダを開く（`explorer.exe /select,`）。PDF の保存に失敗した場合はフォルダを開かない
- 本文：品名・ロット番号・状態・日付・NG 回数、NG の検査（検査名・検査員・NG の No. と検査値）、保存したファイル名（URL が長くなりすぎないようフォルダは書かない）
- 送信はしない。開けなくてもファイルは保存済み。メッセージで知らせる

### 6.3 DB 登録（`検査表DB登録`）
1. チェック（1つでも満たさなければ止める）
   - 明細シートがある／全検査が判定済み／各明細シートに検査者印がある
   - 品名・ロット・日付が正しい（ファイル名と同じチェック）
   - 文字数：品名・ロット番号・状態は100文字以内、検査項目は20文字以内、項目数は10以内
   - 保存履歴に同じ品名・ロットの Excel 保存がある
   - 最新の Excel 保存の後に、表紙（品名・ロット・状態・日付）や明細の入力欄を変えていない。かつ、その保存の OK／NG（ファイル名の【NG】）が今の総合判定と同じ（どちらかに当てはまらなければ「保存の後に入力が変わっています。保存し直してください」）
     - 変えたかどうかは、ブックの非表示の名前 `QA_InputChanged` に記録する（入力を変えたら TRUE、Excel 保存に成功したら FALSE。記録が無いときは変更なしとみなす）
   - DB のパスが https:// でない／DB ファイルがある／ロックファイル（`.~lock.<ファイル名>#`）が無い
2. LibreOffice を起動し、.odb を非表示で開く（同じ .odb が LibreOffice で開かれていれば止める）
3. NG回数を決める：最新の Excel 保存が NG なら、その保存が何回目の NG か（保存履歴で数える）。OK なら 0
4. トランザクション開始。同じ品名＋ロット番号＋NG回数があれば上書き確認（いいえ → ロールバックして終了）。違う NG回数の行には触れない
5. 明細シートの数だけ INSERT。件数を数え直し、合わなければロールバック
6. commit → .odb を保存（store）→ 閉じる。ほかに開いている文書が無ければ LibreOffice を終了
7. 保存履歴に1行（種類＝DB、保存先＝DB のパス）、ブックを上書き保存、「登録しました（○件、NG ○回目／判定 OK）」
- 承認者印は条件にしない（NG のときは承認者印を押せないため）

### 6.4 エラー時のメッセージ
| 状況 | メッセージ |
|---|---|
| LibreOffice が無い／起動できない | LibreOffice を起動できません。インストールを確認してください |
| .odb が開かれている | DB ファイルが開かれています。Base を閉じてから再実行してください |
| SQL エラー | 登録に失敗しました（何も登録されていません）＋エラー内容 |
| store() の失敗 | DB ファイルへの保存に失敗したため、登録できませんでした。もう一度登録してください |
| 下書きを開けない | NG メールの下書きを作れませんでした＋理由（ファイルは保存済み） |

### 6.5 フォーム作成（`フォーム作成`）
- 「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」が必要。無ければ設定方法を表示して止める
- frmApprover（ListBox lstNames、cmdOK、cmdCancel）：電子印鑑シート B3 から下の氏名。OK で `ApplyApproverStamp`
- frmSaveType（CheckBox chkExcel・chkPdf、cmdOK、cmdCancel）：OK で `SetSaveTypes`
- 足りないフォームだけ作る
- 同じ名前のフォームがあれば作らない

### 6.7 基準での判定（modDetail `CheckAgainstStandard` / `JudgeValue`）
- いつ：検査者押印のとき（OK欄の空欄チェックの後、押す人を選ぶ前と、押す直前）
- 使う基準：表紙の品名と検査名でマスタの行を探し、ルール（E列）・基準値1（F列）・基準値2（G列）を使う
- ルール
  - 以上：検査値 ≧ 基準値1 で OK　／　以下：検査値 ≦ 基準値1 で OK　／　範囲：基準値1 ≦ 検査値 ≦ 基準値2 で OK（境界の値は OK）
  - 一致：基準値1 のどれかと同じなら OK。基準値1 は「C,F」のように複数書ける（区切りは , ， 、）。大文字小文字・全角半角・前後の空白は区別しない
- 数値のルールで検査値が空欄・数値でない（全角数字は数値として扱う）、マスタの基準値が数値でない、知らないルール → 判定できないとして押印しない
- 判定結果と OK欄が違う行があれば押印しない。メッセージに、セル・検査値・基準での判定・OK欄と、基準の文を出す
- 総合判定は今までどおり OK欄から決める（照合を通った後なので、基準での判定と同じになる）

### 6.6 表紙ボタンと設定の更新（`表紙ボタンと設定の更新`）

## 8. Claude が決めた細部（違っていれば直す）
| # | 内容 |
|---|---|
| a | NG 回数は保存履歴で数える。NG のまま「保存」を押すたびに1回増える（同じ内容を保存し直しても増える）。保存履歴の行を消すと数え直しになる |
| b | PDF の保存に失敗したときも下書きは開く（添付するファイルが無いことをメッセージで知らせる） |
| c | DB の NG回数は、OK の保存なら 0。OK の行は同じ品名＋ロットで上書き確認になる |
| d | DB 登録は「最新の Excel 保存」の内容を登録する。NG 1回目を登録しないまま2回目を保存すると、1回目は登録できない（各回の保存の後に DB 登録を押す） |
| e | 保存形式のチェックボックスは、最初はどちらもチェックなし |
| f | 既存ブック用に `表紙ボタンと設定の更新` マクロを追加した（表紙ボタンを手で付け替えなくて済むように） |
